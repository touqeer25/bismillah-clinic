WHAT WAS ACTUALLY CODED
• Separate Windows-first Tkinter companion (`tools/screen_parser/`), always-on-top compact control bar. Pick a rectangle on another visible application/browser/PDF; Watch scroll captures settled changed frames without blocking the whole source window. Optional viewer page-counter ROI can trigger sequential page checks; manual `Check page` is the fallback where physical boundaries cannot be detected. Image-file crop/import and optional direct PDF page/text layer are also supported.
• English-only local Tesseract OCR; primary/alternate readings use different preprocessing; per-column frame overlap, exact screenshot dedup, missed-scroll warning. Prescriber, Synthesis-like repertory and Allen-style Materia Medica profiles. Remedy abbreviations checked against the clinic's READ-ONLY `remedy_names.json`; printed counts are not mistaken for remedy grades. If a rubric's grade source/style is unknown, grade remains unverified instead of invented. Colour→grade calibration is PER BOOK and requires confirmation of the printed legend.
• ONE-PAGE GATE: OCR and second-pass/line-level comparison + structure/remedy/grade/page-count checks; up to two CHANGED page OCR retries, or two new cropped OCR readings of a selected problem line; recapture at better zoom or edit OCR/structured fields by hand. An alert may be marked false alarm with a reason, or verified/corrected against the saved source screenshot; every alert must be resolved before human approval, and a grade that is still unknown cannot be approved into clinic JSON. Full-screen review has left frozen source image with zoom-on-alert; right OCR and structured-entry editors. A green automatic check ≠ pixel-perfect guarantee.
• Per-book SQLite ledger and retained cropped source images under `%LOCALAPPDATA%\BismillahClinic\ScreenParser\`: title/edition/source fingerprint, total physical PDF pages vs optional PRINTED label, first/last content pages; each physical page unique and numbered, status/attempt/audit trail, explicit skipped non-content pages with reason; today checked vs newly approved, current-session checked vs newly approved, next required page; resume on restart. OCR/JSON editing drafts autosave to local disk. Jumped/missing/duplicate pages blocked. No screenshot/cloud upload.
• Staging ZIP export only when every in-range physical page is approved or explicitly skipped. Separate app-format payloads: repertory chapter `{rid:{t,r}}` + `_index.json` + master; Allen `mm` `{remedies:{abbr:{name,sections:[{h,p}]}},unmatched}`; Quick Prescriber BOTH library `{sections:[{h,p}]}` and `clinical_index` with only explicit remedy/See references (NO fabricated grade). Includes status/provenance manifest and image hashes, not actual images. This export DOES NOT automatically install/search books inside the clinic: integration + clinic search remain separate future work. Existing data JSON files untouched.
• Installation: Python 3.11–3.13, Tesseract OCR with English data; run `INSTALL_SCREEN_PARSER_WINDOWS.bat`, then `START_SCREEN_PARSER_WINDOWS.bat`. Optional `BUILD_SCREEN_PARSER_EXE_WINDOWS.bat` builds EXE ON WINDOWS (OCR executable remains a local prerequisite). See `tools/screen_parser/README_UR.md` for full Urdu instructions and limits.
• Cache-rule bump in existing web app: parser links `?v=82`, `CACHE_NAME='bhc-clinic-v96'`; no web parsing behavior changed.

LIMITS THAT MUST NOT BE HIDDEN
• This is an English OCR Windows MVP. Automatic physical-page boundary requires a readable dedicated viewer counter; otherwise operator clicks Check page. Initial region picker is for primary monitor. Protected/DRM windows can block capture. Neither independent OCR nor line accounting proves every pixel correct. New/unusual book layouts need a calibrated profile and human review. Do not unzip a generated staging ZIP over live clinic JSON; registering books/adding search is separate work. Keep copyrighted/private books off public GitHub unless licensed.
